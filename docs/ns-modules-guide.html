·整体架构：这套系统是怎么工作的

「智能DNS」不是一个独立产品，而是 GoEdge 平台里的权威 DNS 服务模块——别人买了你的域名解析服务后，把域名的 NS 记录指向你的 DNS 集群，之后所有对该域名的解析请求都会落到你的节点上，由你决定返回什么 IP。

EdgeAdmin（你现在用的后台）
管理界面：建集群、加域名、配记录、看统计
→
edgeapi（控制面）
保存配置到数据库，是唯一的数据源（source of truth）
→
dns-edge（数据面 / NS节点）
真正对外提供 DNS 解析的服务，纯内存缓存，定期从 edgeapi 同步
→
终端用户的 dig / 浏览器
发起 DNS 查询，拿到解析结果

所以你在 EdgeAdmin 里做的每一个操作（建域名、加记录），本质上都是在改 edgeapi 数据库里的一份配置；这份配置再被各个 dns-edge 节点异步拉取过去，真正开始生效。这也是为什么「集群」「节点」是两个不同的东西——集群是逻辑分组，节点才是真正跑 dns-edge、接收查询的机器。

1数据看板

路由 /ns  ·  接口 NSService.ComposeNSBoard

打开「智能DNS」看到的第一个页面。它不是一个可以操作的功能模块，而是把其他模块的数据汇总起来做成一眼能看懂的仪表盘，方便你判断"系统现在整体健不健康、忙不忙"。

看板项含义
NS集群 / NS节点当前有多少个集群、多少台节点在跑，节点数旁边如果出现红字，代表有节点离线了
域名 / 解析记录系统里总共托管了多少个域名，配置了多少条 DNS 记录（A/CNAME/TXT 等）
24小时流量趋势 / 15天流量趋势按小时/按天聚合的查询流量曲线，用来看流量的高峰低谷、是否有异常暴涨
域名访问排行近24小时里被查询最多的域名 Top 10，用来快速定位"谁最忙"
这些统计数据来自 edgeNSRecordHourlyStats 这张按小时聚合的流量表。真实环境里它由 dns-edge 节点上报查询日志累积出来；如果这张表是空的，看板的图表部分就会是空白（只是没数据可画，不代表功能坏了）。

2集群管理

路由 /ns/clusters  ·  接口 NSClusterService / NSNodeService

集群 = 一组共享同一份 DNS 配置的节点。你可以把它理解成"一个 DNS 服务的部署单元"：一个集群下面挂几台机器（节点），这些机器跑的都是同一批域名和记录，互为主备、就近分流，只要有一台还活着，解析服务就不中断。

概念说明
集群（Cluster）逻辑分组，决定了"这批域名归哪套配置管"，本身不直接提供服务
节点（Node）真正运行 dns-edge 进程、监听53端口对外解析的物理/虚拟机
集群主机名（Hosts）这个集群对外暴露的 NS 主机名，例如 ns1.example.com，域名注册商那边要把域名的 NS 记录指向这些主机名
当前版本创建/修改集群时还不能编辑 Hosts、TCP/UDP/TLS/DoH 等细项配置，这部分（"集群设置"完整子菜单，商业版有10个子tab）还在计划里，属于后续要补的功能。

3域名管理

路由 /ns/domains  ·  接口 NSDomainService / NSRecordService

域名管理下面有两层：先加"域名"（比如 example.com），再在域名下加"解析记录"（比如 www.example.com → 1.2.3.4）。一个域名必须先挂到某个集群下，才会被那个集群的节点拿去对外解析。

概念说明
域名（Domain）要托管解析的根域名，需归属到某个集群；同名域名可以在不同集群下各建一份（互不影响）
解析记录（Record）域名下的具体解析条目，支持 A/AAAA/CNAME/MX/TXT/NS/SRV/CAA 等常见类型
域名分组（Group）给域名打标签分类，方便有很多域名时按分组筛选管理
@ 与 通配符记录名填 @ 表示根域名本身；填 * 表示通配符，匹配所有未单独配置的子域名

4线路管理

路由 /ns/routes（含线路分类 /ns/routes/categories）  ·  接口 NSRouteService / NSRouteCategoryService

"线路"解决的问题是：同一个域名，不同地方的人查询，想让他们拿到不同的解析结果（最常见的场景是就近接入——国内用户解析到国内IP，海外用户解析到海外IP）。给一条 DNS 记录关联上"线路"后，系统会根据查询者的来源IP，自动匹配对应线路返回结果，没匹配上任何自定义线路的走默认结果。

概念说明
线路（Route）一段IP范围的集合 + 一个标识，比如"华东电信"对应哪些IP段
线路分类（Category）给线路分组，比如"国内运营商""海外地区"，方便管理大量线路
优先级（Priority）一个IP可能同时命中多条线路时，优先级数字小的线路优先生效
如果你的域名不需要按地区/运营商返回不同结果（比如只有一套服务器），完全可以不配置线路，所有记录默认按无线路处理。

5套餐设置

路由 /ns/plans  ·  接口 NSPlanService

如果 GoEdge 是给外部客户开放自助注册使用的（多租户场景），"套餐"就是用来限制每个用户能用多少资源的模板——类似云服务商的"套餐/规格"。给用户分配一个套餐，就等于给他设定了一组用量上限。

字段作用
套餐名称 / 月价格 / 年价格面向计费展示的基础信息
能力开关（当前版本待扩展）商业版里套餐还能精确控制：是否允许自定义线路、最大域名数、每域名最大记录数、最小TTL、是否支持健康检查/API访问等——这些能力字段目前在「全局配置」里以"新用户默认值"的形式先实现了，套餐维度的精细化控制是下一步

6全局配置

路由 /ns/settings  ·  接口 SysSettingService（通用键值配置，无专用 proto）

整个 NS 模块唯一一处"系统级默认值"设置的地方，不针对具体某个域名或集群，而是影响"新用户/新数据默认长什么样"。

用户默认设置

字段作用
默认集群新用户创建域名时，如果没有指定集群，默认挂到这个集群下
线路支持开关（国家/省份/运营商/Agent/公共）新用户默认能不能用这几类线路，对应"线路管理"里线路的可选范围
功能支持开关（记录统计/域名别名/健康检查/API访问）新用户默认能不能用这几项进阶功能
最大自定义线路数 / 最小TTL / 最大域名数 / 每域名最大记录数 / 每记录最大负载均衡记录数新用户的默认配额上限，0 表示不限

域名归属验证

开启后，用户添加一个不属于自己的域名时需要先证明归属权（常见做法是要求解析一条指定的 TXT 记录），防止有人冒领别人的域名。

访问日志

字段作用
默认记录访问日志全局默认是否把每次查询计入日志/统计，各集群可以单独覆盖这个默认值
记录未匹配域名的查询有人查询了一个系统里根本没有的域名时，要不要也记一笔（用来发现"有人在扫我的DNS"这类情况）
仅记录未匹配到记录的查询域名存在，但查的记录类型/名称没配置时，是否单独记录（用来发现该配的记录没配全）
文档基于 EdgeAdmin 智能DNS模块当前实现（2026-07-02）整理，部分字段/功能标注了与商业版的差异或待办事项。
