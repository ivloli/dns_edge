dns-edge 边缘权威DNS 提测文档

测试环境：admin（贵州）+ api（新加坡 aws-sg-web-obs-05）+ dns-edge（贵州，同 admin 机器）· 更新日期：2026-07-07

说明：dns-edge 是 GoEdge 的自建边缘权威 DNS 节点，EdgeAdmin 里对应两个菜单：域名解析（CDN 域名的解析托管，节点 IP/地理路由由 edgeapi 自动计算推送）和智能DNS（自建任意域名的权威解析，类似自建一个 DNSPod）。本次提测覆盖这两个菜单下的完整功能链路——从建集群/域名/记录，到最终 dig 验证解析结果，两条链路都要走一遍。

0. 环境信息

EdgeAdmin http://111.123.254.177:7788 测试账号找 ivloli 拿
admin 机器 贵州 edge-admin + dns-edge 都在这台机器上
api 机器 aws-sg-web-obs-05（新加坡） edge-api，真正的业务数据库 go-edge-test 也连这台
dns-edge 端口 :5300 DNS 查询端口（UDP+TCP），测试用端口，不是标准 53
注意：这是共享测试环境，同事在这台机器上也有 WAF/CC 防护相关的真实配置数据（策略/规则组），测试时不要碰"服务"、"WAF策略"等无关模块的数据。

1. 域名解析 菜单 — CDN 域名解析链路

路径：域名解析 → 集群列表 / 域名解析 → DNS服务商 / 域名解析 → 问题修复

1

DNS 服务商

域名解析 → DNS服务商 → 添加，类型选 edgeDNSAPI，填 dns-edge 的地址（http://<admin机器IP>:8080）和 AccessKey

保存成功；服务商详情页点"同步域名"能看到 dns-edge 当前手上的域名列表
2

集群 DNS 设置

域名解析 → 集群列表 → 点进某个 CDN 集群 → DNS 设置：绑定主域名、选择上一步建的 DNS 服务商、勾选"自动同步节点状态"

保存后集群详情页能看到分配的 dnsName（例如 g993d53.cdn）
3

节点解析验证

# 集群自己的专属子域名，应该能解析出节点 IP
dig @<admin机器IP> -p 5300 <dnsName>.<主域名> A +short
返回该集群下节点的真实 IP（可能不止一条，权重高的节点出现频率更高）
4

地理路由（ECS 子网匹配）

集群下有多个节点、且节点配置了不同的省份/ISP线路时：

# 带上海电信的测试 IP，应该精确命中配置了"上海+电信"线路的节点
dig @<admin机器IP> -p 5300 <dnsName>.<主域名> A +subnet=122.224.0.1 +short

# 不带 ECS，走权重随机
dig @<admin机器IP> -p 5300 <dnsName>.<主域名> A +short
带 ECS 时稳定返回精确匹配线路的节点 IP；不带 ECS 时在所有候选节点间按权重随机
5

随意子域名（未配置的名字）

dig @<admin机器IP> -p 5300 <随便编的字符串>.<主域名> A +short
查不到任何结果（NXDOMAIN）——除非在集群 DNS 设置的"自动设置的CNAME记录"里手动加了 * 通配符，那种情况下才应该能解析出去
6

"同步"按钮

集群 DNS 设置页面点"同步"按钮

同步成功；再重复一遍第 3-5 步，结果应该跟同步前一致（同步不应该改变任何已有的解析行为）
7

多集群共用同一个域名（如果测试环境有这种配置）

如果同一个主域名下挂了不止一个集群，分别 dig 每个集群自己的 dnsName 子域名

每个集群的子域名都能各自解析到自己的节点 IP，互不影响；某个集群的数据即使因为异常临时缺失，一段时间后也应该被后台自动巡检发现并补上，不需要人工干预
8

问题修复页面

域名解析 → 问题修复

列出当前有解析问题的节点/域名（如果有），可以按提示处理

2. 智能DNS 菜单 — 自建权威解析链路

路径：智能DNS → 集群管理 / 域名管理 / 线路管理 / 套餐设置 / 全局配置

1

集群管理

智能DNS → 集群管理 → 添加集群，填名称保存；进详情页 添加节点

集群、节点都能正常创建；节点详情页能看到接入用的 uniqueId/secret（配到 dns-edge 的 Corefile 里用）
2

域名管理

智能DNS → 域名管理 → 添加域名，绑定到上一步的集群

域名创建成功，列表能看到，且能看到它绑定的集群
3

线路管理

智能DNS → 线路管理，查看内置线路（国家/省份/运营商），也可以尝试添加自定义线路

内置线路列表能看到（如果是空的，找 ivloli 确认是否需要先插入种子数据）
4

记录管理 — 基本增删改查

进入域名详情，添加几种不同类型的记录：

  • @ A 记录，值填一个测试 IP
  • www CNAME 记录，指向别的域名
  • @ MX / TXT 记录
dig @<admin机器IP> -p 5300 <域名> A +short
dig @<admin机器IP> -p 5300 www.<域名> CNAME +short
dig @<admin机器IP> -p 5300 <域名> MX +short
dig @<admin机器IP> -p 5300 <域名> TXT +short
每种类型都能正确 dig 出对应的值；修改记录后立即生效（不用等 TTL）；删除记录后几秒内（不用重启 dns-edge）就查不到了
5

记录线路（智能解析）

给同一个记录名（比如 test）配置两条不同的 A 记录，各自勾选不同的线路：

  • 记录1：值 1.1.1.1，线路勾选"省份-上海"+"运营商-电信"
  • 记录2：值 2.2.2.2，线路勾选"省份-广东"+"运营商-移动"
# 上海电信测试IP，应该精确命中记录1
dig @<admin机器IP> -p 5300 test.<域名> A +subnet=122.224.0.1 +short

# 广东移动测试IP，应该精确命中记录2
dig @<admin机器IP> -p 5300 test.<域名> A +subnet=183.232.0.1 +short

# 不带 ECS，两条都是候选，应该随机
for i in 1 2 3 4 5 6; do dig @<admin机器IP> -p 5300 test.<域名> A +short; done

# 境外 IP，国家都不匹配，同样兜底到全部候选随机
dig @<admin机器IP> -p 5300 test.<域名> A +subnet=8.8.8.0 +short
精确匹配时稳定返回对应记录（不是随机的）；无 ECS / 境外 IP 时两条记录交替出现，不出错
只支持内置线路（国家/省份/运营商），自定义 IP 段 / CIDR / 自定义地域线路暂不支持匹配。
6

通配符记录

给域名加一条名称为 * 的 A 记录

dig @<admin机器IP> -p 5300 <随便编的子域名>.<域名> A +short
任意子域名都能命中这条通配符记录解析出来
7

数据看板

智能DNS → 数据看板

能看到近24小时流量统计、域名/节点排行，没有数据时图表不报错、不崩溃
8

全局配置

智能DNS → 全局配置，设置默认集群、新用户默认套餐能力

保存成功
9

断线重连 / 冷启动同步（需要能操作 dns-edge 进程）

手动重启一次 dns-edge 进程

curl -s http://<admin机器IP>:8080/healthz
dig @<admin机器IP> -p 5300 <域名> A +short
重启后不需要任何人工操作，几秒内 zoneCount 恢复、域名重新可以正常解析
