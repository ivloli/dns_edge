dns-edge 提测文档（边缘权威DNS）

测试环境：admin（贵州）+ api（新加坡 aws-sg-web-obs-05）+ dns-edge（贵州，同 admin 机器）· 更新日期：2026-07-07

背景：dns-edge 是 GoEdge 的自建边缘权威 DNS 节点，支持两种独立模式，本次提测两个模式都要覆盖：
  • CDN 模式（EdgeAdmin 里叫"域名解析" / "DNS服务商"）：edgeapi 主动推送 CDN 域名解析记录到 dns-edge，用于给已有的 CDN 服务加速，本次改动集中在摘除一个意外的自动通配符行为、以及一个自动恢复机制的修复。
  • NS 模式（EdgeAdmin 里叫"智能DNS"）：自己管理任意域名的权威解析，类似自建一个 DNSPod，本次新增了记录线路（智能解析）能力，并修复了一批阻塞性 bug。

0. 环境信息

EdgeAdmin http://111.123.254.177:7788 测试账号找 ivloli 拿

1. 功能范围

1.1 已有能力（历史开发，本次仅回归）

CDN 模式：

  • DNS 服务商管理：添加/编辑/删除服务商（DNSPod、阿里云、自建 edgeDNSAPI 等多种类型）
  • 集群 DNS 设置：绑定主域名、自动同步节点 IP、动态权重、地理路由（ECS 子网 + ip2region，省份/ISP/国家多级降级匹配）
  • 集群 DNS 数据"部分丢失"自动巡检恢复（P12，本次改成了逐域名核对，见 1.3）

智能DNS（NS 模式）：

  • 集群管理：新建/编辑/删除集群，节点管理
  • 域名管理：新建/编辑/删除域名，绑定集群
  • 记录管理：A/AAAA/CNAME/MX/TXT/NS/SRV/CAA 各类型记录的增删改查
  • edgeagent 断线自动重连（dns-edge 主动连 edgeapi 的 gRPC，断线后自动退避重试）
  • 冷启动全量同步（dns-edge 重启后自动拉取全部域名/记录，不需要人工触发）
  • 数据看板（近24小时流量统计、域名/节点排行）

1.2 本次新增 NEW

  • 记录线路（智能解析）：记录可以按"国家/省份/运营商"配置多条不同解析结果，客户端带 EDNS Client Subnet（ECS）查询时按"省份+ISP > 省份 > ISP > 国家 > 默认"优先级降级匹配，跟 CDN 模式已有的地理路由能力一致

1.4 架构调整 CHANGE

摘除了"自动通配符 CNAME"：以前只要给某个 CDN 集群开了 DNS，系统会不经用户同意自动加一条 * 通配符解析——任意子域名（哪怕压根没配置过）都能解析出集群 IP。这个行为经确认是本项目自己加的定制（官方/团队基线分支没有），已经去掉，一共有两处独立实现（后台定时任务 + EdgeAdmin"同步"按钮各一份），都已摘除。现在如果需要泛域名解析，需要在集群的"自动设置的CNAME记录"里手动加一条 *，行为变成用户可见、可控。这个改动只影响 CDN 模式，不影响智能DNS，具体测试步骤见第 2 节。

2. CDN 模式（域名解析）

1

通配符 CNAME 摘除验证

找一个已经配了 DNS 的 CDN 集群（比如测试环境现有的"默认集群"，主域名 test.node），先 dig 一个**随便编的、肯定没配置过**的子域名：

dig @<admin机器IP> -p 5300 <随便编的字符串>.test.node A +short
查不到任何结果（NXDOMAIN），不会解析出集群 IP
2

"同步"按钮不会复现通配符

去这个集群的 DNS 设置页面点一次"同步"按钮，然后重新 dig 同一个随便编的子域名

点击"同步"后依然查不到结果——之前有个遗漏（后台定时任务和"同步"按钮各有一份独立的通配符生成代码，只删了一份），这次两份都已确认摘除，点"同步"不应该再让通配符复现
3

真实记录不受影响

找一条这个集群下真实配置过的具体记录（集群自己的 dnsName 子域名，或者"自动设置的CNAME记录"里手动加的别名），点"同步"前后各 dig 一次

前后结果一致，正常解析，没有被误删
4

P12 自动恢复验证（可选，需要能重启 dns-edge 或人为制造数据缺口）

如果同一个域名下有多个集群共用（比如测试环境的 test.node domain 同时挂了"默认集群"和"test-01"两个集群），重启一次 dns-edge 之后只让其中一个集群的任务重新跑（另一个不用管，模拟"个别集群的数据没跟上"的场景），等待后台自动巡检周期（不需要手动点同步）

一段时间后另一个集群的记录也应该被自动核对出来缺失并补推回来，不需要人工干预（之前的版本这种情况会永远不被发现，除非整个域名都清零）
5

地理路由（ECS）回归

CDN 模式的地理路由是老功能，本次没有改动，走一遍现有的验证方式即可（参考 docs/cdn-cluster-geo-dig-test.md）：

# 带 ECS 子网，应该按省份/ISP/国家优先级匹配到最合适的节点
dig @<admin机器IP> -p 5300 <集群dnsName>.<域名> A +subnet=122.224.0.1 +short
跟之前验证过的结果一致（没有回归）

1

集群管理

智能DNS → 集群管理 → 添加集群（只填名称）→ 保存

保存成功，不再报"服务器出了点小问题"（就是 1.3 里那个 JSON bug）
2

域名管理

智能DNS → 域名管理 → 添加域名 → 集群下拉框选刚才建的集群 → 保存

表单里能看到集群下拉框（之前完全没有这个字段）；保存后域名列表能看到这条记录，不再白屏
3

记录管理 — 增删改查

进入域名详情 → 添加记录（类型 A，随便填个测试 IP）→ 保存 → 记录列表能看到 → 点"修改"改一下值 → 保存 → 点"删除"

添加后记录列表能看到（之前永远是空的）；删除时返回成功，不报 403；dig @<admin机器IP> -p 5300 <记录名>.<域名> A 能查到刚加的值，删除后几秒内（不用重启 dns-edge）就查不到了

4. 智能DNS 记录线路（智能解析）NEW

前置条件：这套测试环境目前 edgeNSRoutes（线路定义表）还没有内置线路种子数据（国家/省份/ISP），需要先联系 ivloli 插入种子数据才能测这一节，否则"线路"下拉框会显示"暂无可用线路"。
1

给记录配置线路

给同一个记录名（比如 test）配置两条不同的 A 记录：

  • 记录1：值 1.1.1.1，线路勾选"省份-上海"+"运营商-电信"
  • 记录2：值 2.2.2.2，线路勾选"省份-广东"+"运营商-移动"
添加/编辑弹窗里能看到"线路"勾选框区域，多选后保存不报错；编辑已有记录时能看到之前勾选的线路被正确回显
2

精确匹配验证

# 上海电信测试IP，应该精确命中记录1
dig @<admin机器IP> -p 5300 test.<域名> A +subnet=122.224.0.1 +short

# 广东移动测试IP，应该精确命中记录2
dig @<admin机器IP> -p 5300 test.<域名> A +subnet=183.232.0.1 +short
第一条稳定返回 1.1.1.1，第二条稳定返回 2.2.2.2（多次执行结果一致，不是随机的）
3

无 ECS / 无匹配时的兜底

# 不带 ECS，两条记录都符合"无地理限制"候选，应该随机
for i in 1 2 3 4 5 6; do dig @<admin机器IP> -p 5300 test.<域名> A +short; done

# 境外IP，两条记录的"国家"都不匹配，同样兜底到全部候选随机
dig @<admin机器IP> -p 5300 test.<域名> A +subnet=8.8.8.0 +short
多次执行能同时看到 1.1.1.1 和 2.2.2.2 两个结果交替出现，不会一直卡死在某一个

4.x 已知限制

  • 只支持内置线路（国家/省份/运营商），不支持自定义 IP 段 / CIDR / 自定义地域线路——这类自定义线路选了也不会生效，属于本次范围之外，后续单独排期
